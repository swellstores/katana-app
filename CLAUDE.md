- **App ID:** katana
- **Project:** Swell integration app for Katana Cloud Inventory (API v1, Bearer API key, 60 req/min). Paid/submitted orders become Katana sales orders matched by SKU (`functions/order-events.ts`, `functions/lib/orders.ts`; retryable errors throw `SwellError` with `retry`). No webhooks: Katana rejects webhook URLs with credentials (500) and Swell routes need a public key, so `katana-poll` (cron every 5 min, `functions/lib/pull.ts`) checks two sources, sales orders (`updated_at_min`) and inventory movements (`created_at_min`), each from its own checkpoint in settings (`orders_checked_at`, `stock_checked_at`). Checks that change something, or must continue next run, are logged in `apps/katana/pulls`. Long syncs are jobs in `apps/katana/syncs` (`inventory`: all Katana stock at the location to Swell; `orders`: existing orders to Katana; `products`: Swell products with stock tracking to Katana with starting stock, `functions/lib/products.ts`). They run step by step in `functions/sync-run.ts` (logic in `functions/lib/jobs.ts`). Retryable errors set `waiting` + `date_retry`, and `sync-retry` (model schedule) resumes them. `sync-control` handles cancel/resume. `inventory-sync` (hourly cron) starts an inventory job. `katana-actions` serves settings, list and order actions.
- **Rules:** credentials/options only in `settings/katana.json`; vitest tests for every function; keep README.md current. Ask before `swell app version`, `swell app release`, or git commits. `swell app push --force` after lib-only changes. In Git Bash set `MSYS_NO_PATHCONV=1` before `swell api` calls with `/` paths.
- **Tools:** Swell skills, Swell CLI, and senior agents for troubleshooting. Consult appropriate skill to ensure competent actions.
